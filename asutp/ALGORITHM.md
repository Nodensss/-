# Информационный расчёт запаса раствора

Расчёт двух независимых связок 321→323 и 315→324 отвечает на вопросы «сколько»,
«на сколько хватит», «когда достигнет неснижаемого остатка». Он не управляет
оборудованием, не формирует сигнализацию, не заменяет регламент, блокировки и ПАЗ.
Прототип не соединяется с АСУ ТП; все сигналы макета имитированы. Внедрение —
службой АСУ ТП по процедуре управления изменениями, после проверки на целевой платформе.

## Входы и параметры

Один экземпляр `FB_PEROX_PAIR` на связку. Условные имена не являются реальными тегами.
В `core/config.ts` находится эталон конфигурации; ST получает коэффициенты параметрами.

| ST | TypeScript | Единица, назначение |
|---|---|---|
| L_SRC | sourceLevelMm | мм источника |
| L_FEED | feedLevel; samples[].level | % для 323, мм для 324 |
| OK_SRC | sourceOk | достоверность источника |
| OK_FEED | feedOk; samples[].ok | достоверность расходной |
| TRANSFER_ON | samples[].transferOn | идёт перекачка, если сигнала нет — FALSE; УТОЧНИТЬ |
| TARGET | targetMm | мм источника, расчётная цель |
| BATCH_MM | batchMm | мм источника, 0 — без партии |
| MANUAL_ON / MANUAL_RATE | manualRatePerHour | ручной расход %/ч или мм/ч; отключение: null |
| SAMPLE_TICK | appendSample | передний фронт минутного такта |
| NOW_MIN | now / 60000 | монотонные минуты внешнего времени; в TS now — миллисекунды |
| RESET | emptyHistory / createPlant | очистить историю и удержанный расход |

| Параметр ST | 321→323 | 315→324 | Свойство config / примечание |
|---|---|---|---|
| K | 38/382, использовать точное отношение | 1.2814 | gainPerMm, %/мм или мм/мм |
| L_DEAD | 30 % | 350 мм | deadLevel |
| L_SRC_MAX | 634 мм | −1 | sourceMaxMm; −1 ST = null TS; УТОЧНИТЬ для 315 |
| L_FEED_MAX | −1 | −1 | feedMax; проверка выключена, УТОЧНИТЬ |
| TARGET | 160 или 0 | 260 или 0 | targetsMm; допускается другое неотрицательное значение |
| BATCH_MM | 382/600/900 | 300/600/900 | batchesMm, допускается другое или 0 |
| WINDOW_MIN | 60 | 60 | windowMin, диапазон 10..120; шаг DT = 1 мин |
| INFLOW_STEP | 0.5 | 3 | inflowStep, рост за один отсчёт; УТОЧНИТЬ по трендам |
| GUARD / SETTLE | 1 / 2 | 1 / 2 | интервалы до/после притока |
| MIN_VALID | 20 мин | 20 мин | minValidMin, при смене окна должен быть ≤ WINDOW_MIN |
| HOLD_MAX | 120 мин | 120 мин | holdMaxMin |
| RATE_MIN | 0.2 %/ч | 1 мм/ч | rateMinPerHour, УТОЧНИТЬ |
| T_WARN / T_URGENT | 2 / 1 ч | 2 / 1 ч | warnHours / urgentHours, УТОЧНИТЬ у технолога |

Входы должны быть конечными числами в инженерных единицах. Служба АСУ ТП
формирует качество FALSE при ошибке измерения, преобразования, выходе за допустимые
пределы и потере связи. Неизвестные пределы датчиков — УТОЧНИТЬ, в макете не выдуманы.
При смене инженерных единиц, коэффициента, окна или шага очистить историю RESET.
Изменение ручного режима, цели и партии историю не сбрасывает.

## Расход по шагам

1. Хранить N+1 отсчёт, N=WINDOW/DT. Эталон TS `appendSample` хранит выбранное окно;
   ST использует кольцо `ARRAY[0..120]` и выбирает последние N+1 значений.
   Повторный такт внутри минуты игнорируется. При пропуске вставить плохие отсчёты,
   без интерполяции. При откате внешнего времени очистить историю и синхронизировать такт.
2. Интервал j соединяет отсчёты j−1 и j. Плохой хотя бы один конец — исключить.
   Приток: флаг на любом конце или положительный рост строго больше INFLOW_STEP.
3. Исключить приток, GUARD интервалов перед ним и SETTLE после него, в пределах окна.
   Перекрывающиеся маски объединяются. На следующем такте маска пересчитывается;
   GUARD может исключить интервал, ранее считавшийся пригодным.
4. Для каждого непрерывного пригодного участка a..b взять L[a]−L[b]. Складывать
   разности концов участков, а не только положительные падения: это сокращает шум.
   T_ok — суммарное время участков, R=ΣΔL/T_ok·60, если время в минутах.
5. Приоритет: текущий датчик недостоверен (7) → ручной расход (6) → достаточно
   пригодных минут (0/1) → последний достоверный расход не старше HOLD_MAX (2) →
   после старта прошло меньше MIN_VALID (3) → нет данных (5).
   Последний расчёт по окну сохраняется с его временем, включая нулевой/отрицательный R.
   Удержанный и ручной расходы не обновляют это время. ST сохраняет только по новому такту.
6. После выбора R, если он меньше RATE_MIN, состояние 4. Прогноз запрещён.
   Равенство RATE_MIN разрешено; равенство HOLD_MAX ещё допускает удержание.

| RATE_STATE | Текст экрана | Прогноз |
|---|---|---|
| 0 | по всему окну (авто) | да |
| 1 | часть окна исключена (перекачка/сбой) | да |
| 2 | расход удержан (N мин назад) | да |
| 3 | накопление данных | нет |
| 4 | нет расхода | нет |
| 5 | нет данных | нет |
| 6 | РУЧН | да |
| 7 | датчик недостоверен | нет |

При старте не подставлять заданный расход имитатора в авторасчёт. При плохом
текущем датчике удержанный расход не разрешает прогноз. При восстановлении
используются пригодные участки окна, при их недостатке — удержание. Перекачка
исключает интервалы, но оставляет расчёт по остальным участкам. Если в окно не
попал приток и сбоев нет, R равен уровню час назад минус текущий.

Режим приложения «по двум замерам»: R=(L_раньше−L_сейчас+X_пер·K)/(минуты/60).
Если R≤0 или интервал≤0 — «проверь замеры». Это ручной источник расхода;
в ST передать результат через MANUAL_RATE, MANUAL_ON=TRUE.

## Прогноз и индикация

- U0=max(L_FEED−L_DEAD,0), H0=U0/R.
- X_SRC=min(max(L_SRC−TARGET,0),L_SRC_MAX), если максимум задан;
  без максимума X_SRC=max(L_SRC−TARGET,0). Ограничение 634 относится к X_SRC,
  как в исходном коде, а не к самому уровню L_SRC.
- ADD_FEED=X_SRC·K, L_FIN=L_FEED+ADD_FEED,
  H1=max(L_FIN−L_DEAD,0)/R. При X_SRC=0 H1=H0; экран пишет «перекачка не нужна».
- H_BATCH=BATCH_MM·K/R при BATCH_MM>0; конец партии — now+H1+H_BATCH.
- OVERFILL: максимум задан и L_FIN>L_FEED_MAX.
  SRC_MIN_NO_OVERFILL=L_SRC−(L_FEED_MAX−L_FEED)/K.
  Это расчётная граница, не команда оборудованию. Если текущий L_FEED уже выше
  максимума, граница окажется выше текущего L_SRC: свободного места нет.
- При плохом источнике H0 остаётся, перекачка и партия недостоверны.
- BELOW_DEAD: L_FEED<L_DEAD. STATUS: 2 СРОЧНО при L_FEED≤L_DEAD или H0<T_URGENT;
  1 ВНИМАНИЕ при H0<T_WARN; 0 НОРМА иначе; 3 НЕТ ПРОГНОЗА при отсутствии H0.
  Статус определяется запасом без будущей перекачки. Нет звука и журнала тревог.

## Соответствие выходов

| ST | core | Единицы / достоверность |
|---|---|---|
| RATE / RATE_VALID | rate.ratePerHour / rate.valid | %/ч или мм/ч |
| RATE_STATE | rate.state | код выше |
| USED_MIN / EXCL_MIN | usedMin / excludedMin | мин |
| TRANSFER_NOW / TRANSFER_IN_WINDOW | transferNow / transferInWindow | флаги |
| HOLD_AGE_MIN | holdAgeMin | мин, −1 / null вне удержания |
| BELOW_DEAD | belowDead | флаг |
| H0 / H0_VALID | hoursBefore / valid | ч |
| X_SRC | sourceMm | мм |
| ADD_FEED / L_FIN | addedFeed / finalLevel | единицы расходной |
| H1 / TRANSFER_VALID | hoursAfter / valid && sourceValid | ч |
| H_BATCH / BATCH_VALID | batchHours / batchHours !== null | ч; 0 партии отключает выход |
| OVERFILL / SRC_MIN_NO_OVERFILL | overfill / sourceMinNoOverfillMm | флаг / мм |
| STATUS | status | 0..3 |
| PARAM_OK | конфигурация PairConfig | проверка параметров экземпляра |

В ST неопределённое числовое значение −1 сопровождается флагом, в TS — null.
Отрицательный измеренный расход также может быть числом: всегда проверять RATE_VALID.
Производные X_SRC/ADD_FEED/L_FIN и OVERFILL могут существовать без расхода;
экран скрывает их при отсутствии прогноза. ST не формирует STRING или время суток.
Экран прибавляет точные часы к внешнему системному времени.

## Проверка и размещение

`npm ci`, `npm test`, `npx tsc --noEmit`, `npm run build`.
`core/vectors.test.ts` читает непосредственно CSV из `test-vectors/`:

- `samples.csv`: отсчёты Б4–Б9, Б11; minute=0..60, Б9=0..14.
- `rates.csv`: ожидаемые R, состояние, минуты; now_minute задаёт конец истории.
  В Б6 last_rate/last_age_min задают начальное сохранённое состояние тестового стенда.
  Для ST стенда предварительно установить hasLast/lastRate/lastRateAt как состояние
  памяти блока (не технологический вход); вариант B6_none проверяется без него.
- `forecasts.csv`: Б1–Б3, Б5, Б10–Б11, обе ветви Б13. Пустое feed_max отключает максимум;
  пустое ожидаемое значение означает null TS / −1 с недостоверностью ST.
- `measurements.csv`: Б12.

Во всех прогнозах now=03.11.2026 08:00 локального времени. Допуск для исходных
округлённых чисел ТЗ ±0.01, для чисел CSV 1e−8. Формат длительности — вниз до
минуты с допуском 1e−6 мин; час окончания вычисляется до округления. Примеры даты:
Б1 «завтра 03:31», партия «завтра 18:43»; Б11 «завтра 04:55», партия «05.11 06:33».

Для ST дополнительно проверить фронт такта (удержание TRUE не добавляет отсчётов),
пропущенные минуты, оборачивание кольца, RESET, плохие параметры, границы удержания,
ручной режим и плохой источник/расходную. Компилятор целевой АСУ ТП в репозитории
не поставляется; TypeScript-тесты не являются исполнением ST. При адаптации
проверить синтаксис стандартных преобразований TRUNC/INT_TO_LREAL/DINT_TO_LREAL,
разрядность LREAL и удержание памяти. Данные в CSV — синтетические.

Считать можно в контроллере, сервере АСУ ТП или архиве: алгоритм один. Уровень
час назад можно брать из архива, но при перекачках нужны промежуточные отсчёты,
качество и маска интервалов. Один только часовой перепад недостаточен.
Реальная платформа, место расчёта, адреса сигналов, привязки качества и такта — УТОЧНИТЬ.
